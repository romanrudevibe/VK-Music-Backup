# VK Save to Spotify

Расширение Chrome для сохранения собственных добавленных аудиозаписей VK и экспорта списка для переноса в Spotify. Текущая сборка: **0.1.16**. Отдельная страница скачивания считает открытия и запросы архива по дням.

## Что уже работает

- Сбор всей коллекции без выбора порциями по 1000; альбомы и чужие плейлисты исключены.
- Очередь, пауза, докачка, сохранение прогресса в браузере.
- MP3 и M4A без перекодирования, корректная кириллица.
- Подключение через открытую вкладку VK, обновление параметров при `bad_hash`.
- До четырёх HLS-фрагментов одновременно, порядок сборки сохраняется.
- TXT «Исполнитель - Название» для переноса списка в Spotify.
- Партнёрский баннер Stadika со ссылкой ROMAN.
- Кнопка «Сообщить о проблеме» готовит редактируемый черновик GitHub Issue. Репозиторий необходимо настроить перед распространением.

## Папки

- `extension/` — исходники расширения; для разработки выбирай эту папку в Chrome.
- `website/` — будущая страница скачивания и сервер статистики.
- `tests/` — проверки, тестовый AAC-фрагмент из mux.js, лицензия рядом.
- `scripts/` — сборка ZIP и настройка ссылки GitHub.
- `docs/` — состояние проекта, перенос, размещение страницы.
- `releases/` — локальные ZIP, включая работавшие 0.1.14 и 0.1.15. Архивы не входят в Git; публикуй их через GitHub Releases.

## Установка и обновление

Собери архив `npm run build`, распакуй его в постоянную папку. В Chrome открой `chrome://extensions`, включи режим разработчика и выбери «Загрузить распакованное расширение». Укажи папку `vk-music-backup` из архива. При обновлении заменяй файлы в **прежней** установленной папке и обновляй карточку расширения — не удаляй расширение, иначе потеряется локальная очередь.

Оставляй открытой «Мою музыку» VK. Подключи VK, собери список и начни с «Проверить 3 трека». Если код 3: оставь одну вкладку VK, обнови её, проверь воспроизведение, выполни требуемый вход или проверку и подключи расширение снова. Если отказы сохраняются, скачай диагностический JSON. Не публикуй аудиофрагменты и данные входа в GitHub Issues.

## Обратная связь через GitHub

Создай репозиторий с включённым разделом Issues, затем выполни:

```sh
python3 scripts/configure_repo.py https://github.com/OWNER/REPOSITORY
npm run build
```

Скрипт настроит одну ссылку для расширения и сайта. Вместо OWNER/REPOSITORY укажи настоящий путь. Пока ссылка пустая, кнопка предлагает скопировать описание проблемы; отправить его автору автоматически невозможно. После настройки кнопка откроет заполненный черновик — пользователь отправит его сам. Версия и код ошибки включены; аккаунт и список музыки не включаются.

Чтобы узнавать о поломках, подпишись на уведомления Issues своего репозитория. Само расширение не отправляет ошибки автоматически.

## Проверки

Требуются Node.js и Python 3.9+:

```sh
npm ci
npm test
python3 -m unittest discover -s tests -p 'test_*.py'
npm run build
```

Проверки сервера открывают порт только на `127.0.0.1`. Они проверяют счётчики, московские границы суток, параллельные записи, пароль раздела автора и CSV. Исходники подключения VK в этой версии не изменены.

## Страница скачивания и статистика

Запуск и размещение описаны в [docs/hosting.md](docs/hosting.md). Раздел автора: `/admin`, логин `admin`, пароль из переменной `VK_STATS_PASSWORD`. Открытия страницы и запросы ZIP хранятся в SQLite по московским дням. Cookies, IP и данные VK в счётчик не записываются. Это **не уникальные люди и не подтверждённые установки**: обновления, боты и повторные скачивания учитываются. CSV доступен только автору.

Сайт пока не размещён в интернете. GitHub Pages сам по себе не запустит Python-сервер и SQLite: потребуется сервер/хостинг с Python и постоянным диском, либо последующая адаптация к другому счётчику.

История текущего чата остаётся в прежнем чате. В новую папку перенесены исходники, документация, имеющиеся проверки и архивы — не пользовательские отчёты и музыка. Публикация на GitHub пока не выполнялась; удалённый репозиторий не настроен.
