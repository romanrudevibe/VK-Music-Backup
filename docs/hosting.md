# Страница скачивания и статистика

## Локальный просмотр

Из корня проекта выполни `python3 website/server.py`. Страница откроется по адресу http://127.0.0.1:8765. ZIP берётся из `releases/vk-music-backup.zip`; сначала выполни `npm run build`.

Для раздела автора задай `VK_STATS_PASSWORD` в окружении до запуска. Имя пользователя: `admin`. Без пароля раздел закрыт. Не сохраняй пароль в Git, URL или исходниках. `/admin` показывает таблицу по дням и общие суммы; `/stats.csv` выгружает CSV.

Счётчик автоматически увеличивается на GET `/` или `/index.html`; GET `/download` увеличивает число запросов скачивания. HEAD, CSS, конфигурация и административные запросы не учитываются. Cookies и идентификаторы посетителей не нужны. Текущая схема включает повторы и ботов, поэтому не называй её числом людей.

## Размещение

1. Выбери хостинг, где можно запустить Python 3.9+ с постоянным диском.
2. Скопируй проект и собранный ZIP. Настрой ссылку GitHub, если она известна.
3. В секретах/переменных сервера задай `VK_STATS_PASSWORD` и, при необходимости, `VK_STATS_DB` — путь к SQLite на постоянном диске.
4. Запускай сервер как службу от отдельного пользователя, по умолчанию на `127.0.0.1:8765`.
5. Поставь перед ним HTTPS-прокси. Сервер рассчитан на работу за прокси, а не на прямое публичное обслуживание Python http.server. Защити `/admin`, `/api/stats`, `/stats.csv` также ограничением частоты запросов на прокси. Не передавай пароль Basic через публичный HTTP.
6. Настрой резервные копии SQLite; не заменяй папку `website/data` при обновлении. Желательно отключить/ограничить журналы доступа прокси, если не нужны IP-адреса.
7. После размещения проверь открытие страницы, ZIP и доступ к статистике с паролем. Только после этого счётчик будет показывать реальных посетителей.

Приложение не хранит IP, но хостинг и прокси могут вести собственные журналы. Код не фильтрует ботов и не вычисляет уникальных посетителей. Публичный хостинг, домен и сервер ещё не выбраны. Денежные обязательства и публикация не выполнялись.
